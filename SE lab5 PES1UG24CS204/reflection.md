# Lab 5 - Reflection

### 1. What is static code analysis?

Static code analysis examines source code without executing
the program. It helps identify potential bugs, security
vulnerabilities, and coding standard violations.

### 2. What did you learn from Pylint?

Pylint helped identify poor coding practices, missing
documentation, naming convention violations, mutable default
arguments, and inconsistent return statements.

### 3. What did you learn from Bandit?

Bandit identified security risks such as hardcoded passwords,
unsafe SQL query construction, and the use of eval().
These findings helped improve the security of the program.

### 4. What did you learn from Flake8?

Flake8 helped identify formatting issues, including excessive
line lengths, missing blank lines, and incorrect comparisons
with None. It helped enforce PEP 8 conventions.

### 5. How does static analysis improve software quality?

Static analysis makes code easier to maintain, understand,
and secure. Finding issues before execution reduces the
possibility of bugs and vulnerabilities reaching production.
Using multiple tools provides complementary checks.
